# 01 · 总体链路架构

> 目标：让你用 30 秒看清「一条 UGC 内容从发布到处置」走完整条链路长什么样，再逐模块拆开讲清职责与边界。

---

## 一、为什么要"一条链路"，而不是"几个独立功能"

机器审核最容易踩的坑，是把它当成"一个打分类的模型"——搞一个模型输出"违规/正常"就完事。但真实业务里，审核要跟**发布、存储、推荐、用户**都联动，而且要能**灰度、能复盘、能处置**。

所以正确的心智模型是一条**流水线（Pipeline）**：内容像原料一样流进去，经过一道道工序，最后产出一个"处置结果 + 一条审核记录"。每一道工序都承担明确职责，任何一道都能单独调参和迭代。

**一句话记忆**：`采集 → 预处理 → 机器初审 → 人工兜底 → 处置 → 落库统计 → 策略平台回控`。

## 三、逐模块职责拆解

### ① 采集层
- 把不同端（App / Web / 小程序 / 评论流）上报的内容统一成**标准内容模型**（Standard Content Model）。
- 计算内容指纹（如 sha256）做**去重**：同一内容二次发布可直接复用首次审核结果，省算力。
- 接入点注意：这一步要快、要稳、不能丢数据，是所有后续的前提。

### ② 预处理层
把"原始内容"转成"机器能判的东西"：
- 文本：去 HTML 标签、去 emoji/特殊字符、分词、拼写纠正。
- 图片：压缩/缩放（保清晰度前提下降传输成本）、色情/暴恐的预检测。
- 视频：**抽帧**（按秒或按关键帧抽取 N 张图）交给图像模型，**抽音频**做语音转写交给文本模型。
- 关键点：预处理直接影响模型效果，脏数据进模型 = 坏判断。

### ③ 机器初审层（链路的核心）
核心是**多层防线 + 命中即判 + 带置信度**，不是单一模型：
- **A 基础规则层**：关键词库、正则、手机号/银行卡/身份证黑库命中。快、可解释、成本低，用于明确违规的硬规则。
- **B 模型层**：文本分类模型（涉政/涉黄/辱骂/诈骗/广告）、多模态分类模型（图片/视频）。给分类 + 置信度。
- **C 用户分层层**：结合用户画像（见 `03-用户分层管理.md`），灰/黑用户直接加严或直接判，跳过冗长规则。
- **D 兜底策略层**：命中某些策略命中要求进人工（断言规则）；或模型低置信度时进人工兜底。

关键设计点：**机器要输出"置信度"和"命中的策略栈"**，而不仅仅是"过/不过"。这样处置层和人工层才有依据，复盘才有抓手。

### ④ 人工复核层（兜底）
- 机器全量判，人工抽审 + 待审队列兜底。
- 平台要有人工审核台：列队、展示内容与机器判断依据、一键判定。
- 关键点：**人审结果要回流给模型当样本**（反馈闭环），这是审核准确率持续提升的燃料。

### ⑤ 处置层
按命中策略与用户层，给出处置动作：
- **通过** → 上架
- **拦截** → 删除/不予发布
- **限流/降权** → 降低推荐曝光（针对低质/灰用户）
- **违规计次 / 处罚** → 记入用户档案，累积后升级处置（禁言/封号）

### ⑥ 存储与统计层
- 每条审核记录落库（谁、何时、命中什么策略、机器判什么、人判什么）。
- 策略命中打点、指标聚合（详见 `04-指标与复盘体系.md`）。
- 数据是后面复盘和调策略的依据，**一定要留痕、可追溯**。

### ⑦ 策略管理平台
- 运营/审核团队在这里：配置策略、看指标、灰度上线、下架策略、管理用户分层、做复盘。
- 相当于整条链路的"控制台"。

## 四、关键设计决策：双引擎演进

早期业务量小时，往往一套简单"关键词 + 规则"就够。随规模上来，会演进成两套引擎，建议在一开始就把边界划清楚：

| | **规则引擎（Rule）** | **模型引擎（Model）** |
| --- | --- | --- |
| 判定依据 | 明确的关键词 / 正则 / 黑库命中 | 模型概率 / 多模态分类 |
| 特点 | 快、可解释、便宜、准确率高但覆盖窄 | 覆盖广、能处理语义/复杂场景，但不可解释、有误判 |
| 更新方式 | 人工加规则，秒级生效 | 训练/迭代模型，需样本与周期 |
| 典型应用 | 明确违规词、手机号、身份证、硬黄暴 | 语义涉政、变体违规、图像视频识别 |

**正确姿势**：两条引擎并行，规则命中先短路，规则漏掉的部分由模型兜住；两边命中情况都打点，用数据判断要不要加规则 / 训模型。**永远不要让"不可解释"的模型独自决定终审。**

---

## 五、链路设计的三个铁律

1. **机器只负责"初筛"，人负责"兜底"**：机器全量初筛，命中高风险/低置信度进人工，保证不失控。
2. **每一步都留痕**：策略命中、模型置信度、人审结论都要落库，否则无法复盘和追责。
3. **分层与策略要联动**：同一个内容，普通用户命中 A 判正常，黑名单用户命中 A 直接拦截——处置不是内容一个维度决定的。

---

## 六、最小可行实现（MVP）建议

如果从零搭，别一上来就上大模型集群。按这个顺序把骨架立起来：
1. **规则引擎 + 内容指纹去重**：先跑起来，覆盖明确违规。
2. **一个文本分类模型 + 人工兜底抽审**：覆盖语义违规。
3. **用户分层表**：先按最简单（白/灰/黑）把处置挂上。
4. **落库 + 看板指标**：能看出命中率、误判漏判，才有迭代的依据。
5. 最后再上图像/视频模型、复杂灰度、自动分层。
