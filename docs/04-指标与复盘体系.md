# 04 · 指标与复盘体系

> 目标：用数据回答"审核做得好不好、该往哪调"。这是整条链路里唯一能持续把系统调优、让策略和分层"越用越准"的环节。

---

## 一、核心指标框架

审核的本质是在 **召回率（抓得全，少漏判）** 和 **准确率（抓得准，少误判）** 之间权衡。围绕这条主线，把指标分成四类：

### 1. 违规类指标（红线，看漏判）
| 指标 | 定义 | 关注点 |
| --- | --- | --- |
| **漏判率** | 违规内容被判正常的比例 | 越低越好，这是合规底线 |
| **涉政/涉黄漏过数** | 高危漏过内容 | 必须绝对压低，监管红线 |
| **人工复查漏判率** | 人工抽审中又发现漏判的比例 | 衡量机器初审能力 |

### 2. 误伤类指标（红线，看误判）
| 指标 | 定义 | 关注点 |
| --- | --- | --- |
| **误判率** | 正常内容被判违规的比例 | 越低越好，这是用户体验底线 |
| **误拦截数** | 被误删/误降权的正常内容 | 直接伤用户，要重点监控 |
| **申诉通过率** | 申诉后被平反的比例 | 高 = 误伤多，低 = 该申诉的不通过 |

### 3. 效率类指标（看成本与时效）
| 指标 | 定义 | 关注点 |
| --- | --- | --- |
| **机器审核通过率** | 机器直接判过的比例 | 越高，人工成本越低 |
| **人工介入率** | 进人工复核的比例 | 越低越好，但太低可能漏判 |
| **审核时效 / 积压量** | 一条内容多久出结果、积压多少 | 决定用户体验，不能压太久 |

### 4. 兜底类指标（看人工质量）
| 指标 | 定义 | 关注点 |
| --- | --- | --- |
| **人工审核准确率** | 人审结论的正确率 | 人也会错，要抽检 |
| **抽检/复核比例** | 人工复核机器结果的抽样率 | 保证机器判断有质量监督 |

## 二、两类"最容易搞混"的指标：误判 vs 漏判

这是审核复盘里最需要拎清的：

| | **误判（false positive）** | **漏判（false negative）** |
| --- | --- | --- |
| 是什么 | 正常内容被判成违规 | 违规内容被判成正常 |
| 伤谁 | 伤**正常用户**（体验） | 埋**合规风险**（安全） |
| 典型动作 | 平台方降低误判，开放申诉平反 | 平台方加严策略，人工兜底 |
| 代价 | 用户流失、投诉、舆论 | 被处罚、下架、刑责风险 |

**复盘时必须分开看**：误判率上升了，不一定是策略错了，可能是白名单收得太窄；漏判率上升了，可能是模型更新后阈值放太松。**不能混在一起看，否则不知道往哪调。**

---

## 三、关键方法论：兜底抽样（为什么人审只审一部分）

机器无法 100% 准确，所以要人工兜底。但人工也审不过来全量，怎么办？——**抽样**。

### 抽样原则
1. **高风险必抽**：命中高危策略/黑名单用户的内容，100% 进人工。
2. **低置信度抽**：模型低置信度内容，送人工。
3. **随机抽检**：正常内容随机抽样一定比例，用来评估"机器有没有把违规漏放"。
4. **分层抽检**：不同用户层用不同抽样率（黑名单高、白名单低）。

### 抽样要能推算出总体
- 抽样的核心目的是用**样本反推总体**的漏判率/误判率。
- 所以抽样必须**随机 + 有代表性**，否则算出来的指标失真，会误导调优。

## 四、反馈闭环：人审结果回流（最重要）

**这是审核系统持续变准的燃料。** 没有反馈闭环，机器永远停留在初始水平。

```
机器初审结果
   → 部分内容进人工兜底
   → 人审给出"真值"（这个内容到底违不违规）
   → 人审结果回流：
       - 覆盖"真值"的样本喂给模型重新训练/微调
       - 用于校准策略置信度阈值
       - 用于评估机器初审的漏判/误判率
```

**关键点**：人审的"真值"要单独存、和机器的判断对比，才能算出准确的漏判/误判率。人审结论本身也要被抽检（人也会错）。

## 五、复盘流程（系统化地"开会找问题"）

一套标准的复盘节奏：

### 1. 定义周期与范围
- 按周/按月复盘；确定复盘的内容范围（文本/图片/视频？哪些策略？）。

### 2. 拉指标，看异常
- 把漏判率、误判率、申诉通过率、人工介入率等拉出来，标出异常波动的指标。

### 3. 定位原因（下钻）
- 指标异常 → 下钻到"哪条策略、哪个用户层、哪个模型版本"在变。
- 例：误判率上升 → 发现是某条新灰度策略误伤白名单 → 回滚或调阈值。

### 4. 做假设与验证
- 提出"漏判是不是某类变体词没进词表" → 在影子模式验证 → 数据说话。

### 5. 形成改进项
- 结论落到具体动作：加词、调阈值、训模型、收白名单、改分层规则。

### 6. 上线 + 跟踪
- 改进项灰度上线 → 下一周期复盘验证是否改善 → 形成闭环。

---

## 六、复盘必须回答的 6 个问题

每次复盘，逼自己对这 6 个问题有答案，复盘才有效：
1. 这个周期**漏判了哪些高危内容**？为什么没拦住？
2. 这个周期**误伤了哪些正常用户**？为什么误伤？
3. **策略/模型版本**改动后，指标变好了还是变坏了？
4. **用户分层**有没有误划？申诉通过率正常吗？
5. **人工兜底**质量如何？抽检准确率达标吗？
6. 下个周期**优先级最高的改进项**是什么？

---

## 七、指标看板的呈现建议

| 视图 | 看什么 |
| --- | --- |
| **全局总览** | 机器通过率、人工介入率、违规处置量趋势 |
| **漏判监控** | 漏判率、高危漏过数（红线，最高优监控） |
| **误伤监控** | 误判率、申诉通过率、误拦截数 |
| **策略版本对比** | 不同版本策略的召回/准确对比 |
| **用户层下钻** | 每个用户层的漏判/误判/介入率 |
| **人工质量** | 抽检准确率、人审与机器一致率 |

---

## 八、指标与用户分层/策略的联动（三者的闭环）

```
策略 → 决定"内容怎么判"
用户分层 → 决定"对不同人怎么判"
指标 → 决定"判得好不好、往哪调"
   ↑_______________________
   每周期复盘，反过来调策略和分层
```

**复盘是驱动整套系统进化的引擎**：没有指标就没有调优依据，没有调优链路就停止进步。
