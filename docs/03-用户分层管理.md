# 03 · 用户分层管理

> 目标：把"用户"从抽象概念变成可操作的**信用/风险分层**，让审核能针对不同的人用不同的力度。这是机器审核从"一刀切"走向"精细化"的关键。

---

## 一、为什么要用户分层

如果所有用户、所有内容都用同一套策略，会有两个问题：
1. **效率浪费**：高信任老用户被反复严格审核，体验差、审核成本高。
2. **风险漏洞**：黑产、恶意用户用一套策略防不住，反复试探。

**用户分层的本质**：按用户的历史行为与信任度，把用户分成不同层级，对不同层级**用不同的审核力度 + 不同的处置**。

分层让审核从一维（只看内容）变成二维（内容 × 用户）。

---

## 二、分层模型（推荐：白/灰/黑 + 细分）

最简单也最常用的分层是 **白名单 / 灰名单 / 黑名单**，可在此之上再细分：

| 层级 | 名称 | 特征 | 典型来源 | 审核力度 |
| --- | --- | --- | --- | --- |
| **L1** | 高信任白名单 | 长期无违规、优质创作者 | 老用户、认证号、机构号 | 极宽松，抽审，直接上架 |
| **L2** | 普通用户 | 正常行为，无劣迹 | 绝大多数注册用户 | 标准策略 |
| **L3** | 灰名单/待观察 | 有轻微违规、行为可疑 | 首次违规、被举报、敏感时段活跃 | 加严策略，部分进人工 |
| **L4** | 风险用户 | 多次违规、投诉集中 | 累计违规计次超标 | 全量加严，命中即处置 |
| **L5** | 黑名单 | 确认恶意/黑产 | 封号解封、诈骗确认、设备黑产 | 直接拦截，最高优先级 |

**分层是可变的**：用户层级应随行为动态调整，不是一成不变。

---

## 三、分层的业务作用（分层到底能带来什么）

| 作用 | 说明 | 示例 |
| --- | --- | --- |
| **降低误伤** | 白名单用户减少误判拦截 | 老创作者发长文不再被误拦 |
| **提高拦截效率** | 黑/灰用户命中即判，省算力 | 黑名单用户发广告词秒拦截 |
| **动态处置** | 同一内容不同人处置不同 | 普通用户限流，黑用户直接删 |
| **成本控制** | 优质用户抽审，风险用户全量 | 把人力集中到风险用户身上 |

**核心一句话**：分层让有限的审核资源（算力+人力）向**高风险用户**倾斜。

---

## 四、用户分层怎么实现（落地）

### 1. 用什么特征给用户打分（分层特征）
- **行为特征**：发布频次、违规次数、被举报次数、投诉量、异常时段活跃。
- **信任特征**：注册时长、实名/认证状态、粉丝/互动质量、历史审核通过率。
- **设备/环境特征**：设备指纹、IP 段、黑产设备、注册/登录异常。

### 2. 打分模型（简单版）
每个维度给分，加权汇总得到**信用分**：

```
信用分 = w1*行为分 + w2*信任分 + w3*设备分
用户层 = 信用分映射到 [白/灰/黑]
```

- 维度分可以来自**统计规则**（如违规次数的阶梯分）或**模型**（如行为异常模型）。
- 关键点：打分要**可解释、可调整**，运营能看懂为什么一个用户被划到灰名单。

### 3. 动态更新（分层不是算一次就完）
- **触发式**：发生关键事件（违规、被举报、解封）立即重算该用户层级。
- **定期式**：按天/周对全量用户分层刷新，吸收新增历史行为。
- **灰度**：新分层规则先在影子模式评估，再逐步放量，避免把正常用户错划成风险用户。

## 五、分层 × 策略 联动（与 02 接起来）

前面 `02-审核策略体系` 讲策略按"内容风险"分 L1~L5。这里讲"用户层"，两者要**组合**起来：

```
处置判定 = f( 内容风险策略命中  ×  用户层 )
```

一个内容触发某条策略后，最终处置由用户层决定：
- 白名单用户 → 内容风险命中 → 抽审/降权即可（宽容）。
- 灰/风险用户 → 命中 → 直接拦截 + 违规计次（加严）。
- 黑名单用户 → 命中 → 最高优先级直接删除（最严）。

> **这就是二维判定的核心**：不是"内容违规就删"，而是"内容违规 × 你是哪层用户"决定处置。

---

## 六、分层管理的反误伤与申诉

用户分层最大的风险是**误伤**——把正常用户错划成风险用户，导致误拦截、误降权。所以必须配：

1. **申诉机制**：被降权/拦截的用户可申诉，申诉通过后恢复层级。
2. **人工复核**：分层变更（尤其升级到黑名单）要有人工确认，不能全自动。
3. **缓存与回滚**：分层结果缓存可回滚，错划后能批量纠正。
4. **留痕**：每次分层变更记录"原因+时间+操作者"，可追溯。

**铁律**：分层是"辅助判断"，最终高风险处置（尤其封号）必须有人工兜底确认。

## 七、用户分层数据模型（最小表结构）

| 字段 | 说明 |
| --- | --- |
| user_id | 用户 ID |
| credit_score | 信用分 |
| user_level | 白/灰/风险/黑 或 数字层 |
| level_source | 来源：规则打分 / 模型 / 人工 |
| updated_at | 最近一次分层更新时间 |
| reason | 分层变更原因 |
