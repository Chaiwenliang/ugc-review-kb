# 02 · 审核策略体系

> 目标：把"什么内容算什么、怎么处置"沉淀成**可配置、可灰度、可下线、可复盘**的规则集合。这是机器审核链路里最需要细心打磨的一环。

---

## 一、什么是"策略"

**策略 = 一段可配置的判定逻辑**，描述"当满足什么条件时，对什么内容，做什么处置"。

一个策略至少包含三要素：

```
条件 (Condition)  →  判定/计算  →  动作 (Action)
   输入是什么          怎么判           输出什么处置
```

示例（文本违规策略）：
```yaml
name: 涉政敏感词命中
条件:
  - 文本命中 [关键词库: 涉政黑名单]   # 输入
  - 且 用户层 in [普通, 灰]           # 结合用户
判定:
  命中数 >= 1 → 置信度=0.99, 分类=涉政, 命中断言=Y
动作:
  处置 = 拦截; 违规计次+1; 送人工复核确认
```

**策略与模型的区别**：模型输出的是一个"概率 + 分类"，策略输出的是"明确的处置动作 + 依据"。策略可以把多个模型/规则/用户信息编排成一条可解释的判定链。

---

## 二、策略的分层（重要）

策略不是一锅粥，要分层。推荐按"风险确定性"从高到低排：

| 层级 | 名称 | 特点 | 典型动作 |
| --- | --- | --- | --- |
| **L1 硬规则** | 确定性最高 | 命中即判，无需模型，秒级生效 | 手机号/身份证/银行卡、明确涉黄涉暴关键词 |
| **L2 规则+用户** | 结合用户画像 | 普通用户宽松、灰黑用户加严 | 敏感词+黑名单直接拦截 |
| **L3 模型弱规则** | 模型给出高置信分类 | 置信度>阈值当规则用 | 高置信涉政/涉黄直接拦截 |
| **L4 模型待定** | 低置信/语义模糊 | 进人工兜底 | 送人工审核队列 |
| **L5 人工策略** | 运营手动加的策略 | 临时活动/热点补丁 | 手动拦截/下架 |

**为什么要分层**：因为每一层的"代价"不同——L1 便宜但覆盖窄，L5 成本高但灵活。分层让你能**把算力和人力花在刀刃上**：确定性高的用规则秒判，模糊的才上模型和人工。

## 三、策略模板（可复用的几种典型形态）

把最常见的策略抽象成模板，新业务直接套：

### 1. 关键词/正则命中模板
```yaml
条件: 文本 正则匹配 [黑名单词表]
动作: 分类=违规词; 处置=拦截; 违规计次+1
```
- 适用：明确违规、广告词、辱骂词、硬黄暴。
- 注意：词表要**分级**（高置信/低置信），要能**灰度加词**（先观察误判率再放量）。

### 2. 模型分类 + 置信度阈值模板
```yaml
条件: 模型分类=涉政 AND 置信度>=0.9
动作: 处置=拦截; 送人工确认
```
- 适用：语义类违规。
- 关键参数：**置信度阈值**是权衡召回/准确的核心旋钮（见 `04-指标与复盘`）。

### 3. 用户层联动模板
```yaml
条件: 用户层=黑名单
动作: 全量加严, 任何命中策略都升级处置, 直接拦截优先
```
- 适用：风控联动。
- 关键点：**同一内容在不同用户层下处置不同**——这是用户分层的核心价值（见 `03`）。

### 4. 组合策略模板（AND / OR / NOT）
```yaml
条件:
  AND:
    - 模型分类=广告
    - NOT 用户层=高信任白名单
动作: 限流/降权
```
- 适用：多条件复合判断，避免单一维度误伤。

### 5. 断言兜底模板
```yaml
条件: 命中 [断言白名单策略] OR 模型置信度<0.5
动作: 进人工
```
- 适用：拿不准的绝不机器终判，强制人工兜底。

## 四、策略的版本与灰度（关键工程能力）

策略一旦上线，影响所有线上内容。所以策略必须**能灰度、能回滚**：

### 灰度流程
```
开发新策略
  → 影子模式（shadow）：只计算不打真实处置，记录"如果命中会怎样"，和线上并跑评估
  → 小流量灰度（如 1%~5% 流量）：仅对灰度流量真实处置
  → 观察误判率/漏判率/投诉量
  → 达标则逐步放量（5%→20%→50%→100%）
  → 全量上线；不达标则回滚 / 调整
```

### 版本管理要点
- 策略带 **version + 生效时间 + 生效范围（流量比例/用户层）**。
- 每次改动是**新版本**，可随时**回滚到上一版**（防误上线）。
- 命中策略时记录**策略版本号**，保证复盘时能追溯到"当时用的是哪版策略"。
- 支持**策略权重**：同层多个策略可配置权重/优先级，避免冲突。

## 五、策略上线前的自检清单（Checks）

上线任何策略前，问自己这几条：

1. **判定依据可解释吗？** —— 这条策略命中了，我能跟运营/监管讲清楚为什么吗？
2. **会不会误伤正常用户？** —— 有没有配套的白名单 / 置信度门槛 / 小流量灰度？
3. **处置合理吗？** —— 是删除、拦截、还是限流降权？会不会太狠/太轻？
4. **有据可查吗？** —— 命中后是否打点、落库、带版本号？
5. **可回滚吗？** —— 出问题能立刻下架或回滚到上一版吗？
6. **要不要人工兜底？** —— 这条是"模型终判"还是"进人工"？是不是所有高风险都进人工确认？
